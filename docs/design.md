# malchut 設計

Markdown からスライドショーを生成・発表する Wayland ネイティブアプリ。
Rust + GTK4 で実装し、描画は WebView を使わず Cairo + Pango で自前で行う。

## 1. 機能

- Markdown からスライドを生成し、ファイル保存に追従してリアルタイム更新
- Marp を参考にした構文と、画像配置の拡張構文
- 発表者ノート
- コードハイライト、Mermaid 図
- テーマ切り替え
- PDF 出力
- プレゼンモード(スライド画面 + 発表者画面の2画面同期)
- サムネイルモード(一覧から任意のスライドへジャンプ)
- キーボード操作(ホットキー)

対象外: 内蔵エディタ、数式、インライン HTML、Marp の CSS テーマ互換。

## 2. アーキテクチャ

```
slides.md ─parse→ Vec<Slide> ─layout(theme)→ DisplayList ─paint→ Cairo
                                                                  ├ スライド画面
                                                                  ├ 発表者画面 (現在 / 次)
                                                                  ├ サムネイル
                                                                  └ PDF
```

- **parse**: `comrak` の AST をトップレベルの `---` で分割し、
  `Slide { blocks, directives, notes, backgrounds }` を直接組み立てる。
- **layout**: 論理座標で配置を計算し、描画命令列の `DisplayList` を作る。
- **paint**: `DisplayList` を Cairo に流す。表示先ごとの違いは拡大率だけ。

### 論理座標

| 比率 | 論理サイズ |
|---|---|
| 16:9 | 1920×1080 |
| 4:3 | 1440×1080 |

- 高さを 1080 に揃え、テーマの文字サイズ指定を両比率で共有する。
- 構文中の px 指定(`w:400`、`round:16` など)は、この論理座標での値。
- Pango の hint metrics を切り、サムネイルと全画面で折り返し位置を揃える。

### クレート構成

| クレート | 内容 |
|---|---|
| `malchut-core` | parse / theme / layout / paint / PDF 出力。GTK 非依存でヘッドレスにテスト可能 |
| `malchut` | GTK4 アプリと CLI(`malchut slides.md`、`malchut export slides.md -o out.pdf`) |

主な依存: `gtk4`, `cairo-rs`, `pango` / `pangocairo`, `comrak`, `syntect` + `two-face`,
`merman`, `librsvg`, `gdk-pixbuf`, `notify`, `clap`, `serde` + `toml`。

relm4 と libadwaita は使わない(ほぼカスタム描画でウィジェットが少ないため)。

## 3. 構文

構文の拡張機構(構文パスの分離、汎用属性の中間層、構文バージョン)は持たない。
構文を変えたらスライド側を直す前提とする。

- **front matter**: `theme`, `size`(16:9 / 4:3), `paginate`, `header`, `footer`
- **スライド区切り**: `---`
- **ディレクティブ**: `<!-- class: lead -->` は以降すべて、
  `<!-- _class: lead -->` はそのスライドだけに効く。
- **発表者ノート**: ディレクティブ以外の HTML コメント
- **未知のキー**: `key:value` 形式で解釈できないものは、ソース位置付きの警告として
  プレビューに表示する。`key:value` 形式でないトークンは alt テキストとして扱う。

### リンク

| 記法 | 動作 |
|---|---|
| `[text](#3)` | 3 枚目のスライドへ移動 |
| `[text](#見出し)` | その見出しを持つスライドへ移動 |
| `[text](https://...)` | 既定のアプリ(ブラウザなど)で開く |
| `[text](notes.pdf)` | Markdown ファイルからの相対パスとして、既定のアプリで開く |

- 見出しのアンカー名は GitHub と同じ規則で作る(小文字化、空白は `-`、記号は除去。
  同名の見出しには `-1`, `-2` を付ける)。
- リンクはスライド画面でも発表者画面でもクリックできる。リンクの上ではポインタの形が変わる。
- 行き先の無いスライド内参照は、警告として表示する。
- PDF にもリンクとして埋め込む(スライド内参照はページへのリンクになる)。

### 画像

alt テキストに指定を並べる。

| 記法 | 意味 |
|---|---|
| `w:400` `h:300`(`%` も可) | サイズ。`%` はスライド幅・高さ比 |
| `bg` / `bg fit\|cover\|contain` | 背景画像 |
| `bg left:40%` / `bg right:40%` | 背景を片側に分割配置 |
| `at:70%,20%` | 絶対配置(本文の流れから外す) |
| `anchor:center` | `at` の基準点 |
| `align:left\|center\|right` | 流れの中での横位置 |
| `side:right w:40%` | 画像を片側に置き、本文を残りの幅に流す |
| `crop:x,y,w,h` | トリミング |
| `round:16` `shadow` `opacity:.6` | 装飾 |
| `darken` `darken:0.6` | 黒に寄せて暗くする(値は強さ 0〜1、省略時 0.5) |
| `lighten` `lighten:0.6` | 白に寄せて明るくする(値は強さ 0〜1、省略時 0.5) |
| 同一段落に画像を複数並べる | 自動で横並び |
| `![...](a.png "caption")` | キャプション |

補足:

- 画像のパスは Markdown ファイルからの相対パス。SVG はベクターのまま描く。
- `w:` / `h:` は片方だけ指定すると縦横比を保つ。`%` の基準は、流れの中の画像なら本文領域、
  `at:` の画像ならスライド全体。
- 流れの中の画像は既定で中央に置き、幅と残りの高さに収まるよう縮める。
- `bg` の既定は `cover`。`left` / `right` は割合を省略すると 50%。
- `side:` の幅は `w:` で指定し、省略時は本文領域の 40%。1 スライドに 1 枚まで。
- `anchor:` は `top-left`(既定), `top`, `top-right`, `left`, `center`, `right`,
  `bottom-left`, `bottom`, `bottom-right`。
- `crop:` の値は元画像に対する px か `%`。
- `darken` / `lighten` は、背景画像の上の文字を読みやすくするためのもの。背景以外の画像にも使える。
  画像の透明な部分には色を載せない。両方書いた場合は後に書いたほうが効く。
  スライドの背景色に寄せたい場合は `opacity:` を使う(画像が透けて背景色が混ざる)。
- 画像は画像だけの段落に書く。文中に混ぜた画像は未対応で、警告を出す。
- 読み込めない画像は、その場所にメッセージを表示する。

### 例

```markdown
---
theme: default
paginate: true
---
<!-- _class: lead -->
# タイトル

---
## 構成
- 箇条書き

![side:right w:40% round:12](arch.svg "全体図")

<!-- ここは発表者ノート -->
```

## 4. コードブロック

言語名が `mermaid` なら図、それ以外はハイライトとする。

### ハイライト

- `syntect` を使い、不足する言語は `two-face` で補う。
- 配色はテーマで指定する。
- 情報文字列で行強調と行番号を指定できる(`rust {2,4-6} numbered`)。
- 幅からあふれる場合は折り返さず、下限付きで自動縮小する。
- 結果は Pango の属性付きテキストなので、PDF でも選択可能なベクターになる。

### Mermaid

- Rust ネイティブ実装の `merman` を使い、SVG にして librsvg で描く。
  - 同じ図で比較した結果: `merman` は本家 `mmdc` とほぼ同じ配置で 1 枚 3ms、
    `mermaid-rs-renderer` は 23ms で配置が本家と異なり、`mmdc` は 775ms かつ
    ラベルが `foreignObject` で出力され librsvg では文字が消える。
  - `merman` は `resvg-safe` パイプラインを指定し、ラベルを SVG のテキストで出力させる。
- 描画は十分速いので、レイアウト時に同期で行う。ワーカースレッドとプレースホルダは使わない。
- 結果は(ソース + 配色)のハッシュをキーにメモリ上へキャッシュする。ディスクキャッシュは持たない。
- テーマのパレットとフォントを init ディレクティブのテーマ変数として渡し、色を揃える。
  ソース自身が init ディレクティブを持つ場合はそちらを優先する。
- 大きさは、図の文字が本文より少し小さくなる倍率を基準に、残りの領域へ収まるよう縮める。
  横位置は中央に置く。
- 構文エラーは図の位置にメッセージとソースを表示し、アプリは止めない。

## 5. 状態管理と画面

状態は単一プロセスの `AppState`(スライド列、現在位置、タイマー、テーマ)に集約する。
各ウィンドウは `Action`(Next / Prev / Goto(n) / ToggleOverview / TimerStart など)を送り、
変更通知を受けて再描画する。2画面の同期はこれで成立する。

### 描画の先読み

スライドの切り替えを速くするため、表示領域ごとに描画済みの画像を 4 枚まで持つ
(表示中、1 枚先、1 枚前、2 枚先)。

- 表示中のスライドを描いたあと、アイドル時に前後のスライドを 1 枚ずつ描いておく。
- 画像は表示領域のデバイスピクセルの大きさで持つ。領域の大きさが変わったら描き直す。
- レイアウト結果が変わったスライド(内容、テーマ、画像の変更)は、画像も描き直す。
- 番号指定などで離れたスライドへ飛んだときは、その場で描く。

### プレビューモード(起動時)

1ウィンドウで表示し、保存に追従する。

### プレゼンモード

スライドウィンドウと発表者ウィンドウを開く。

- `fullscreen_on_monitor` でモニタを指定して全画面化する
  (Wayland ではアプリからウィンドウ位置を指定できないため)。
- モニタが1枚なら通常ウィンドウ2枚で開く。
- 画面入れ替えキーを用意する。
- プレゼン中はアイドル抑止を入れる。

### 発表者画面

- 現在スライド(大)、次スライド(小)
- 発表者ノート(あれば)
- 経過タイマー、開始/一時停止ボタン、リセットボタン
- `n / N`、現在時刻

### サムネイルモード

各ウィンドウ内のオーバーレイとしてグリッド表示する。スライド画面でも発表者画面でも使える。

- 表示状態はウィンドウごとで、同期しない。発表者側で開いても聴衆側には出ない。
- ジャンプ結果だけを同期する。

## 6. ホットキー

どちらのウィンドウにフォーカスがあっても同じキーが効く。

| 操作 | キー |
|---|---|
| 終了 | `q` / `Ctrl+Q` |
| スライド送り | `→` `↓` `Space` `PageDown` `l` `j` |
| スライド戻し | `←` `↑` `Backspace` `PageUp` `h` `k` |
| タイマー開始/一時停止 | `t` |
| タイマーリセット | `Shift+T` |
| サムネイルモード切り替え | `g` |
| 明示的な再読み込み | `Ctrl+R` |
| プレゼンモード開始 | `F5` |
| プレゼンモード終了/サムネイルを閉じる | `Esc` |
| 全画面切り替え | `f` / `F11` |
| スライド画面と発表者画面の入れ替え | `s` |
| 先頭/末尾へ | `Home` / `End` |
| 番号指定ジャンプ | 数字 + `Enter` |
| テーマ切り替え | `Shift+→` / `Shift+←` |

- **クリッカー対応**: プレゼンリモコンは `PageDown` / `PageUp` を送るものが多いので、
  送り・戻しに含める。
- **サムネイルモード中**: 矢印と `hjkl` は選択の移動になり、`Enter` でジャンプ、
  `g` か `Esc` で閉じる。
- **再読み込みの範囲**: Markdown、テーマ、画像を読み直し、メモリ上のキャッシュを捨てる。
- **実装**: 各ウィンドウのキーイベント(キャプチャ段階)を直接受けて `Action` に変換する。
  サムネイルモード中だけ矢印キーの意味が変わるので、アクセラレータではなく自前で振り分ける。
- **キー設定の変更**: 当面は固定。設定ファイルでの変更は必要になってから足す。

## 7. リアルタイム更新

- `notify` で親ディレクトリを監視し、50〜100ms のデバウンス後に再パースする
  (親ディレクトリを見るのは、エディタの rename 保存に対応するため)。
- 参照画像とテーマファイルも監視する。画像は、スライドが参照しているファイルの
  あるディレクトリを随時監視に加える。
- スライド単位で(ソース + テーマ + サイズ)のハッシュを取り、
  変更のないスライドの `DisplayList` とサムネイルを再利用する。
- プレビューモードでは、変更された最初のスライドへ自動で移動する(設定で無効化可)。
- front matter のエラー時は直前の正常な状態を保持し、エラーをオーバーレイ表示する。
- 本文が枠からあふれたスライドには、プレビュー時のみ警告マークを出す。

## 8. テーマ

- 形式は `theme.toml` とアセット(フォント、背景画像)のディレクトリ。
- 内容はパレット、フォント、要素別スタイル(h1〜h6, p, li, code, blockquote, table)、
  余白、コード配色、`class` ごとの上書き(`lead`, `invert` など)。
- フォントサイズや余白は高さ 1080 の論理座標を前提に定義する。
- 探索順は `./themes/`、`$XDG_CONFIG_HOME/malchut/themes/`、組み込みテーマ(default / dark)。
- 切り替えは front matter、`--theme`、実行中のキー操作のいずれでもできる。
- テーマファイルの変更にも追従する。

## 9. PDF 出力

- Cairo の PDF surface に、1スライド1ページで同じ paint を流す。
- ページサイズは論理座標を 0.5 倍する(16:9 なら 960×540pt = 13.33×7.5 インチ)。
  1920×1080pt のままだと、ビューアによっては巨大な用紙として扱われるため。
- テキストは選択可能なベクター、SVG もベクターのまま。
- CLI と GUI メニューの両方から実行できる。

## 10. テスト

- Markdown → `Slide` のスナップショットテスト(`insta`)を最小限置く。
- 描画は、組み込みテーマと画像入りのスライドが失敗せず描けることを確認する。
- GUI は Xvfb 上で起動し、xdotool のキー入力とスクリーンショットで確認する
  (GTK の X11 バックエンドを使う。モニタ指定の全画面化は実機で確認する)。

## 11. 実装順

1. core: parse → layout → paint、PDF export CLI、コードハイライト
2. Mermaid の組み込み
3. プレビューウィンドウとライブリロード
4. 画像拡張構文と背景画像
5. プレゼンモード(2ウィンドウ、発表者画面、タイマー)
6. サムネイルモード
7. テーマ切り替え
